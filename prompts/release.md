# Release: write the changelog

You are preparing the **v0.1.0** release of **__PROJECT_TITLE__**.

__PROJECT_PITCH__

Look at the project's git history (`git log --oneline`) and `TASKS.md` to see
what was actually built, then write a `CHANGELOG.md` file in the repo root
with a `## v0.1.0` entry summarizing the notable changes as a short bullet
list, in [Keep a Changelog](https://keepachangelog.com/) style. If
`CHANGELOG.md` already exists, add the new entry at the top instead of
overwriting the rest of the file.

Write the file directly with your file tools. Do not reply with the
changelog text itself -- just write `CHANGELOG.md` and confirm briefly once
it's done.
